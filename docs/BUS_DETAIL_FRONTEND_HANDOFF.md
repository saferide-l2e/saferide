# SafeRide FE-07 — bus details and driver's limited public profile

Design: https://www.figma.com/design/ztF1QqN7Npu55gnJwZVrG7

## Delivered UI

- Mobile-first bus and driver profile page, private-field-safe Django template, bus artwork and responsive CSS.
- Departure time, boarding point, route/destination, public driver display name, vehicle type/plate, server-provided available seats.
- Clear one-seat / ten-minute check-in/expiry terms and cancel explanation.
- Secure POST-only reserve or waitlist form with csrf_token when backend explicitly supplies action URLs and eligibility flags.
- Missing bus, no seats, closed boarding, booking rejected/error and verification-gate states.
- An actual synthetic-data disclosure on the detail screen.
- No hardcoded driver phone number, license document, incidents or public safety score.

## Backend handoff

BE-04 owns departure filtering and the public bus detail view. BE-05 owns reservation and server-side inventory, and BE-07 owns the waitlist action.

Render passenger/bus_detail.html with a context object named bus containing these server-approved public fields:

- route_label, scheduled_departure_at or scheduled_departure_display (Lagos-local time string, with timezone label if displayed).
- boarding_point, destination_point.
- vehicle_type_display, plate_display (only the approved public representation).
- driver_public_name, optional driver_initials, driver_approved boolean.
- is_open, is_full, available_seats derived on server under eligibility and inventory rules.

Additional context: search_url (back-link); reserve_action / waitlist_action, each generated by Django reverse (never from untrusted query parameters); can_reserve / can_join_waitlist boolean (only guidance — actual server permission must still be checked on POST); verification_url, action_message, info_message, error_message; optional approved route_notices with title, message, published_at. Never send private identity documents, full contact numbers, complaints, unmoderated notices or driver safety risk scores to the browser.

Backend checks: hold duration exactly 600 seconds from server UTC; waitlist offers 120 seconds; driver/vehicle approvals; role, suspended/verified status; last-seat concurrency, duplicate holds, expired boarding and CSRF. A page being rendered does NOT confer booking access.
