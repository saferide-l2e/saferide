# SafeRide — simple guide for every teammate
We are building a website to help people find a bus, hold one seat for 10 minutes, board safely with a code, and record the ride. The driver also sees **limited, approved passenger details**. We use **fake people and pretend ID checks** for the Friday demo.

## Your three teams
- **Frontend:** Make the pages people see, including forms and phone-size designs. Work in `templates/` and `static/`.
- **Backend:** Make the buttons really work: log in, find bus, reserve, wait, check in, finish ride. Work in Django services, forms and views.
- **Database:** Decide what information is stored. Build models, migrations, safety rules and test data. Use PostgreSQL.

## How to work and learn
1. Open the GitHub Issues page and pick **your assigned task**.
2. Read every requirement and try the small examples in the issue.
3. Learn one tool at a time: read a short Django or HTML lesson, then build one small part.
4. Ask for help in your issue when stuck. Tell the group what you tried.
5. Create a new branch. Never overwrite a teammate's code or push to main.
6. Test your work. Show a good result **and** a bad/edge case.
7. Open a Pull Request. Ask one teammate to check it, then merge when ready.
8. Each evening, share: done / next / help needed.

## Friday presentation
**Everyone must practice a 30–60-second explanation** of their work. Volunteer to pitch the product! We need people who can explain the problem, demonstrate the ride flow, and answer questions. Aim for simple words, clear screenshots and a calm live demo. Speaking is also a skill we are here to learn.
