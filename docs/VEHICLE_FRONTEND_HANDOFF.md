# FE-04 — driver vehicle onboarding and approval-status screens

Responsive form and vehicle list templates built for the shared Figma design.

BE-03 must provide authenticated driver-only views and model forms with vehicle_type, plate_display and seat_capacity. The form context supplies can_register, form_action, form, vehicle_list_url, verification_url and any error/status text. Validation for positive seat count, plate normalization and duplicate plate is done SERVER-SIDE. Staff controls approval, not the driver.

The list context provides server-filtered **current driver's own** vehicles with plate_display, vehicle_type_display, seat_capacity, approval_status, can_publish, publish_url and optional review_note. Approval status values: PENDING, APPROVED, REJECTED, SUSPENDED. Only an APPROVED vehicle with can_publish true receives a publish link, which must be generated by Django reverse. The backend must always recheck driver and vehicle permissions.

This PR is frontend-only: no URL/view, database writes, staff approval or working departure publication. Real PostgreSQL validation, unauthorized-driver tests, manual keyboard/360px/200%-zoom and teammate review are outstanding.
